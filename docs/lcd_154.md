# Waveshare ESP32-S3-LCD-1.54: a small colour screen that turns itself

A 240x240 colour LCD with an accelerometer. It shows the platform's full
colour PNGs (the `rgb` profile, like the HDMI TV in `docs/hdmi_tv.md`) and
finds by itself which edge is up: the server always sends the upright page,
the board turns it. Started 2026-10-16 on the bench board `02:00:00:00:00:08`.

Env: `waveshare_esp32s3_lcd_154` (`esp32/platformio.ini`). Factory
flash backed up on 2026-10-16 to
`esp32/backups/lcd154_factory_020000000008.bin` (16 MB, SHA-256
`c67aff60…bdd7bf`); restore with
`esptool.py --port <port> write_flash 0 <file>`.

## The board

The non-touch variant (no CST816: the factory demo is Waveshare's touch
build and logs a harmless touch init failure). Pins from Waveshare's own
demo, `waveshareteam/ESP32-S3-Touch-LCD-1.54`, ESP-IDF `01_factory/components/esp_bsp`.

| Part | Detail | Pins |
| --- | --- | --- |
| SoC | ESP32-S3R8, 240 MHz, 16 MB QIO flash, 8 MB octal PSRAM, native USB | |
| Screen | 1.54" IPS 240x240, ST7789, RGB565, colours inverted (`INVON`) | MOSI 39, SCLK 38, CS 21, DC 45, RST 40 |
| Backlight | PWM, active high | 46 |
| I2C | codecs and accelerometer | SDA 42, SCL 41 |
| Accelerometer | QMI8658 at 0x6B (`WHO_AM_I` 0x05) | I2C |
| Speaker | ES8311 at 0x18, NS4150B amplifier | I2S MCLK 8, BCLK 9, LRCK 10, DOUT 12; amplifier 7 |
| Microphones | 2, ES7210 | I2S DIN 11 |
| Battery | 3.7 V, ADC on GPIO1 (x3 divider), charging GPIO3 (low) | power hold GPIO2 (high keeps it on) |
| Buttons | BOOT, PLUS, PWR (all active low) | 0, 4, 5 |
| microSD | SDMMC 4-bit | 13-18 |

No RTC chip and no PMIC.

## What it declares

`/schedule?…&w=240&h=240&caps=v1:rgb,screen_size1,welcome_local1,self_orient1,power_report1,stays_awake1,wake_alarm,audio_out,tune_mml1,sound_list1,scene2,motion1,pwr_short1&in=a,b&pwr=ext&ori=<turn>`

- `rgb`, `screen_size1`: full-colour PNG at 240x240 from `/pic/4displayB5.png`.
  Until a server knows it as `rgb` the PNG URL answers 406, and the firmware
  falls back to the 1-bit BMP.
- `self_orient1` (`backoffice/device_capabilities.py`): the server renders
  every publication upright and landscape, ignores a publication's own axis,
  hides `set_orientation` and refuses a changed orientation; the owner and
  admin pages say "automatic". `ori=` is the clockwise quarter turn the board
  applies now, stored as `reported_orientation` and shown by
  `get_orientation` → `device_orientation`, for information only: nothing
  renders again when the board is turned. Only a square panel can do this
  without laying the page out again.
- `wake_alarm`, `audio_out`, `tune_mml1`, `sound_list1`: the ES8311 speaker,
  through the same code as the PhotoPainter (`audio_hal.cpp`,
  `alarm_clock_hal.cpp`), so alarms, pushed sounds, MML tunes and the list of
  upcoming sounds. No RTC chip: a sound wakes the board by the ESP32's timer
  ("timer backup only"), irrelevant while it never sleeps. BOOT, PLUS and a
  short press on PWR stop a ring. The microphones are not declared: nothing
  reads them.
- `scene2` (since 2026-10-21: the scene runtime 2, `docs/scene_runtime.md`;
  before it `scene1`, `scene_turn1`, `scene_sound1`, `scene_tone1`),
  `motion1`, `pwr_short1`, with `in=a,b` (BOOT, PLUS): plays scenes
  (`scene_player.cpp`, `docs/scenes.md`). The page is the 240x240 square
  either way up and the board turns it whole (`DisplayHAL::setTurn`), so a
  scene's `layouts` has one entry: the scene keeps playing when turned.
  Seen on the board against production on 2026-10-21: the instrument, mail,
  dice, Pomodoro, quiz and analogue clock targets, and a scene compiled
  again for `scene2` on its own (`docs/scene_runtime.md` "Seen on the board").
- `pwr=ext` while the charger charges (GPIO3 low) or a computer is on its USB
  (`Serial.isPlugged()`), else `pwr=bat`; nothing on the board senses USB
  power itself, so a wall charger with a full cell reads as battery.
  `stays_awake1`: it never deep-sleeps and syncs at the powered cadence (10 s
  by default, `WIGNET_ALWAYS_POWERED`) whatever `pwr=` says.

## Welcome page

The server draws the Welcome page of every `rgb` screen in the same look as
this board's own screens (`welcomePage.render_dark_welcome`): #F7F2E8 on
black, the address in #D56668, Bitstream Vera, all flush left. A small
"Welcome" in regular weight with the mark at the top, the QR code centred
vertically, the caption and address on the last two lines. The code stays
dark on a #F7F2E8 tile with a two-module quiet zone, since not every phone
reads a light-on-dark code. The
HDMI TV is `rgb` too, so it gets the same page. E-paper screens keep black
on white.

## Text messages

Full-colour screens are colour screens for text too: `background` and
`text_color` count on `push_event`, `add_slide` and `set_slides`, and
`set_message_background` sets the default (white on `rgb`, so a TV keeps
black on white). "White" text is drawn in #F7F2E8 on `rgb`
(`publications.RGB_TEXT_INKS`); a white background stays white.

## Firmware

- `src/board.h`: each board's features and pins (`WIGNET_HAS_AUDIO`, I2C,
  I2S, amplifier, buttons, PWR polarity, PMIC rail, RTC interrupt). The audio
  and alarm code tests features, not the PhotoPainter.
- The built-in sound, `data/morning_elasticity.wav`, lives on LittleFS
  (`board_build.filesystem = littlefs`), uploaded once with
  `pio run -e waveshare_esp32s3_lcd_154 -t uploadfs`. On an Apple Silicon Mac
  without Rosetta PlatformIO's `mklittlefs` (x86_64 only) cannot run; the
  image was built on 2026-10-16 with `littlefs-python` (block 4096, 864
  blocks, read/prog 128, name_max 64, disk version 2.0) and written with
  `esptool.py write_flash 0xc90000 littlefs.bin`. Without the file a sound
  rings as an 880 Hz tone; tunes need nothing.

- `src/hal/waveshare_esp32s3_lcd.cpp` (shared with the 2" board, `docs/lcd_2.md`): an upright RGB565 frame in PSRAM.
  A GxEPD2 driver writes main.cpp's 1-bit pages (startup, provisioning, BMP)
  into it at rotation 0; `displayPngFromStream()` (main.cpp) decodes a PNG
  into a scratch frame and copies it in only once it decoded completely at
  240x240. `showFrame()` sends it to the panel turned by `setTurn()`, in
  software, row by row (`MADCTL` stays native).
- `src/orientation_hal.cpp`: the QMI8658 at +-4 g, polled every 200 ms in a
  task of its own, so the screen turns even while setup() waits in the Wi-Fi
  portal or the loop on a download (a lock in the HAL sends one frame at a
  time). A new turn must hold 600 ms, at least 35 degrees from a diagonal,
  and lying flat keeps the last one. The sensor is mounted facing away from
  the screen (z = -1 g lying screen up), so its x axis is the screen's left:
  the table at the top of the file, measured on 2026-10-16. The task owns
  the I2C bus; the codec will have to share it.
- Its own screens are English, in the brand colours: text #F7F2E8 on
  black, small print #D56668 (#332021 was tried as the background on
  2026-10-16 and dropped).
  - Power-on: the picture `assets/boot_lcd154.png` (the Wignet mark,
    120x60) centred on black. `embed_boot_image.py` embeds the PNG as-is
    into `src/boot_image.h` before each build (`--check` for staleness); the
    firmware blends its transparency onto the background. Swapping the file
    changes the screen, at most 240x240. The backlight stays off until this
    first frame has reached the panel: nothing white flashes first.
  - Wi-Fi setup, then "connected" until the platform's first page:
    left-aligned, FreeSans 12 pt (the network name in FreeSansBold 12 pt:
    18 pt does not fit with a 16 px margin) and Org_01 at size 1 for the
    small print, all bundled with Adafruit GFX.

  `LcdFrame` (main.cpp) draws them straight into the frame, in colour; text
  sent to the local web page still uses the 1-bit built-in font.
- Battery (`src/power_hold_hal.cpp`, `WIGNET_POWER_HOLD_PIN=2`): the battery
  only feeds the board while GPIO2 is high, so the firmware sets it first
  thing in setup(); before that, unplugging USB switched the board off. A
  press on PWR (GPIO5) of 2 s that starts after boot lets go of it, which is
  how to switch the board off on battery (on USB it keeps running). Until the
  battery work lands it behaves exactly as plugged in: awake, the powered
  cadence (`stays_awake1`), only its reported `pwr=` telling the two apart.
- Scenes (`src/scene_player.cpp`, `WIGNET_SCENES`), since 2026-10-17: the
  board declares `scene1` and `in=a,b` (BOOT, PLUS; PWR stays the board's) and
  plays what `/schedule` names with LVGL (docs/scenes.md, "The player");
  since 2026-10-19 also `scene_sound1`: a scene's `sound` action plays a tune
  once on the speaker.
- Battery level (`src/power_hal.cpp`, `WIGNET_BATTERY_ADC_PIN=1`,
  `WIGNET_BATTERY_DIVIDER=3`, `WIGNET_CHARGE_PIN=3`), since 2026-10-17:
  reported only. `/schedule` carries `bat=` (a percentage from a rest LiPo
  curve, rough), `mv=` (16 ADC samples x 3) and `chg=` (GPIO3 low: charging),
  with `pwr=` as above (since 2026-10-19; `pwr=ext` always before), while
  power and sleep stay as plugged in. A reading outside 3000-4400 mV is left out (no cell, or a
  floating pin). The bench `power` command prints the raw ADC, the divider,
  the charge pin and the query. First reading on `02:00:00:00:00:08`, battery fitted,
  on USB: 1365 mV x 3 = 4092 mV, 94%, `chg=0` (the charge pin high: a full
  cell, or the pin's meaning still to confirm by plugging in a drained one).
- Colour calibration (`waveshare_esp32s3_lcd.cpp`): at full backlight the
  panel shows a cool white and lifts dark tones (#F7F2E8 read as white,
  #332021 as a light brown). Picked by eye on 2026-10-16 from test cards sent
  over the bench console, against the brand colours on a Mac screen: a gamma
  of 1.75 on top of the panel's own, then green x0.97 and blue x0.90. Applied
  to every frame on its way out (lookup tables, panel in 18-bit mode, so
  shadows keep 6 bits a channel), platform PNGs included: the server sends
  the same colours to every screen.
- Wi-Fi portal (shared by every ESP32 board): tapping a network shows a
  spinner at once, since the next page comes from the board itself; and the
  pages ask for `/static/x?v=<content hash>` (`embed_portal.py`), which the
  board lets the phone cache, so the password page loads 4 KB instead of
  31 KB again. Picking a network took 1-2 s before (2026-10-16).
- Bench console: `image` takes a BMP or a 240x240 PNG
  (`commands (images: bmp png):`). It also answers while the Wi-Fi portal
  blocks setup() (a task polls it until Wi-Fi is set), so test cards work on
  a board with no network yet.
